### 数据阵列的寻址约定

参考源码的三层数据是**扁平数组**，第 `n` 层为 `floor[n]` / `role[n]` / `item[n]`：

```
数组下标 = y × 11 + x          x, y ∈ [0, 10]，y 向下增长
```

例：`floor[10][115] = 4` 表示第 10 层 `(x=5, y=10)` 放置了「上楼梯」，因为 `10 × 11 + 5 = 115`。
本项目在 `tools/import-mota50.mjs` 中按同一约定解析。

## 2. 数据来源优先级

当参考源码与其他来源冲突时，本项目的取舍：

| 数据类型 | 权威来源 | 理由 |
|---|---|---|
| 怪物 HP/ATK/DEF/金币 | 参考源码 → 与社区基准帖核对 | 两处一致才采信 |
| **战斗公式** | **`motajs/mota-js`（BSD-3）** | 参考源码实现错误 |
| 地图布局 | 参考源码 | 唯一的完整地图数据来源 |
| 11 层以后的剧情机制 | 社区攻略 / NPC 对白 | 参考源码未实现 |
| 经验值 / 等级 | **不存在** | 三处独立来源一致证实原版无此系统 |

各数值的具体核对记录见 `docs/mota50-numeric-system.md` §1。

## 3. 授权边界（重要）

### 3.1 归档代码

`source/` 与 `LICENSE/` 中的代码是 **GPL-3.0 作品**，版权归原作者所有。
本项目归档它们**仅用于阅读、对照与数值考证**，不参与构建、不打进产物。

### 3.2 ⚠️ 派生数据同样受 GPL-3.0 约束

`data/floors/*.json`、`data/monsters.json`、`data/tiles.json`、`data/floor-notes.json`、
`data/monster-placement.json` 是**从 `mota50-data.js` 转换而来**的。

**「转换成另一种格式」不构成「独立创作」。** 按 GPL-3.0 的通例理解，这些派生数据属于**衍生作品**，
原则上应同样以 GPL-3.0 分发。这不是法律意见，但**在发布前必须当作一个真实约束来处理**。

### 3.3 对本项目最实际的影响

目标平台是**微信小游戏**。GPL-3.0 的实际影响是：

- GPL-3.0 **不是**「禁止商用」，商用可以，但要求衍生作品整体以 GPL-3.0 开源并附完整源码。
- 微信小游戏的分发形态（代码包）能否满足 GPL 的「对应源码可得」要求，需要单独判断。
- 若计划闭源发布，**不能**直接使用这批派生数据。

### 3.4 可选的处理路径

| 路径 | 做法 | 代价 |
|---|---|---|
| **A. 接受 GPL-3.0** | 整体以 GPL-3.0 开源，附完整源码 | 无法闭源；需处理小游戏分发形态的合规 |
| **B. 换数据源** | 改用 `motajs/mota-js`（**BSD-3-Clause**，宽松）的地图数据 | 需重新做一次导入与数值核对；BSD-3 只要求保留版权声明 |
| **C. 原创关卡** | 保留数值体系（公式与数字属事实性内容，不构成表达），**地图布局全部自己设计** | 工作量最大，但版权最干净，且能自由调整难度曲线 |
| **D. 沙盒自用** | 只在本地研究、不外发 | 无风险，但也无产物 |

> **数值 vs 表达的区别：** 「兽人 HP 260 / ATK 85 / DEF 5」这种事实性数据通常不受著作权保护；
> 但**具体的关卡布局**（哪一格放什么、门的排列方式）属于创造性的表达，受保护程度高得多。
> 路径 C 正是利用了这条区别。

### 3.5 对白文本：故意不复制

`mota50-action.js` 中有两个对白数组（`wiserWord` 智者的 51 条提示、`traderWord` 商人的 12 条商品叫卖），
它们既有**机制信息**也有**文学表达**：

| 部分 | 性质 | 本项目的处理 |
|---|---|---|
| 「第 27 层应达到 HP1500 / ATK80 / DEF98」「十字架克制兽人与吸血鬼」 | 事实性数值与规则 | ✅ 提取进 `data/floor-notes.json` 的 `dialogueDerivedFacts` |
| 「勇士，我怎么会在这看到您？我也不知道怎么来到此处？」 | 创造性表达 | ❌ **未复制**，需自行撰写 |

**这是有意的取舍：** 事实可以自由使用，原文句子复制会显著扩大 GPL 衍生的范围。
复刻时请在 `data/` 中自行撰写对白——**同时也能避免与上游的文本雷同**。

**建议：在决定发布形态之前，先确定走哪条路径。** 若打算闭源，C 或 B 是必选。

## 4. 参考源码的已知缺陷

归档是为了**考证**，不是为了**照抄**。以下问题在使用参考源码时必须绕开：

### 4.1 战斗公式错误（严重）

`mota50-fight.js` 只扣一回合伤害：

```js
if( player.hp > (enm.att - player.def) ){
    player.hp -= (enm.att - player.def);   // ← 没有回合数循环
    return true;
}
```

**没有计算击杀所需回合数。** 用它做数值预期会系统性低估损失。
本项目战斗公式以 `motajs/mota-js` 的 `calDamage` 为准，详见 `docs/mota50-numeric-system.md` §3.3。

### 4.2 事件仅实现前 10 层

`eventHappened` 的分支只覆盖与 1~10 层相关的剧情（含 `floor[10][115]=4` 生成上楼梯）。
11 层以后的楼层机制改由攻略文字考证，记录在 `data/floor-notes.json`。

### 4.3 十字架只判定吸血鬼

`fight.js` 中 `if(enm.id===8)` 只对吸血鬼（id 8）做攻击力翻倍，
但攻略实测数字要求**兽人与兽人武士同样翻倍**（兽人武士 264→76）。

本项目新增 `crossVulnerable` trait 覆盖三者，见 `data/monsters.json` 的 `traitsReference`。

### 4.4 地形判定遗漏「星际空间」

`checkFloor` 的阻挡分支未包含星际空间（图例 6，即第 50 层的地形）。
本项目按原版语义判定为**不可通行**，见 `data/tiles.json` 的 `legend["6"].note`。

### 4.5 部分内容从未放置

| 类别 | 未放置项 |
|---|---|
| 怪物 | 吸血鬼（roleId 8）、真魔王 |
| 道具 | 怪物书(10)、地震卷轴(15)、对称飞行器(16)、屠龙剑(21) |
| NPC | 小偷(34)、仙子(35) |

前三类在原版中由剧情或商人提供，属于参考实现的未完成部分。
完整清单与影响见 `docs/known-gaps.md`。
